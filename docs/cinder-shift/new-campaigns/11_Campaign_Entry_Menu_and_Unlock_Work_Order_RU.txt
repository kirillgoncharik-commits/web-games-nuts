1. ПОВЕДЕНИЕ
Главное меню → «Кампании» → три художественно оформленные карточки:
— первая кампания Кальдеры 7 — доступна с начала;
— «Маленькая смена» (c02-small-world);
— «Адриатический сигнал» (c03-adriatic-1986).
Обе новые кампании открываются после первого успешного завершения первой кампании. После открытия игрок сам выбирает любой из двух миров; проходить «Маленькую смену» перед Югославией не требуется.
Это заменяет прежнее правило свободного входа в новые миры без прохождения первой кампании. Независимые сохранения/экономика при этом сохраняются.

Использовать фактический ID первой кампании из текущего registry, не придумывать новый ID и не переименовывать старое сохранение.
Сначала проверить свежий билд и уже существующее меню/финал; дополнить готовое вместо создания дублирующего экрана.

2. КАРТОЧКИ И ВХОД
В карточке: cover/key art, локализуемое название и краткое описание, статус доступности, собственный прогресс миссий, понятное основное действие.
locked: замок + «Завершите первую кампанию»; artwork/название видимы, начало недоступно. Причина читается без hover.
available_not_started: «Начать» → briefing/первая миссия выбранной кампании.
in_progress: «Продолжить» → её последний валидный checkpoint. «Начать заново» — отдельное действие с указанием конкретной кампании и подтверждением сброса только её прохождения.
completed: отметка завершения + доступ к повтору/выбору уже доступных миссий.
Внутри кампании оставить действующее правило открытия/повтора миссий; не вводить дополнительные замки или глобально открывать все 40 комнат одним нажатием.
Выбор карточки и запуск — разные действия: случайный tap по обложке не сбрасывает активное прохождение.

Базовая кампания остаётся доступной после открытия новых миров. Можно вернуться к её Replay/Continue без потери статуса других кампаний.
Смена кампании не переносит wallet, покупки, run state и reward ledger между namespaces; общие настройки языка/звука/input сохраняются.

3. ФИНАЛ ПЕРВОЙ КАМПАНИИ
После подтверждённой победы показать итог первой кампании и сообщение «Открыты новые кампании».
Основной CTA «Выбрать новую кампанию» ведёт в selector с обеими новыми карточками unlocked; вторичный — в главное меню/повтор по действующему UX.
Не загружать автоматически один из новых миров и не требовать заново пройти всю первую кампанию.
Повторный callback/повтор финала/reload не создают дублирующие unlock/reward операции. После перезапуска новые миры доступны из обычного меню.
Уведомление об открытии показывается один раз на подтверждённое событие, но само право выбора не зависит от просмотра уведомления/нажатия CTA.

4. ПРАВИЛО ДОСТУПА И СОХРАНЕНИЕ
Источник права — устойчивый profile-level факт первого завершения базовой кампании (completion fact / ledger по текущему save contract).
Не использовать только текущую выбранную миссию, URL, временный флаг компонента меню или один локальный UI state.
Факт завершения и связанные финальные результаты записываются согласованно. Unlock можно вычислять из этого сохранённого факта; не создавать две независимые расходящиеся истины.
Запись через существующий SaveRepository и разрешённый host/local storage adapter; отдельный сервер не нужен.
Запуск первой кампании заново не удаляет уже заработанное открытие новых миров. Полный сброс профиля — отдельное явно обозначенное действие, с соответствующим предупреждением.
Язык, PB и прогресс остальных кампаний не сбрасываются при выборе/повторе.
Если запись не удалась — честный статус/повтор записи, без обещания сохранения после reload; не очищать последний целый save.

Completion должен происходить в обычном прохождении базовой кампании. Победа в отдельной Time Attack/Score Attack миссии, score/share code или получение рекламной награды не считаются завершением кампании.
Поддерживаемый импорт валидного профильного сохранения с зафиксированным завершением сохраняет право доступа; share/Rival/Relay код не является таким сохранением.
Это локальная продуктовая логика, не серверный anti-cheat.

Миграции:
— старый профиль с надёжным признаком завершённой базовой кампании → создать/нормализовать completion fact, сохранить все данные;
— неполная/отсутствующая информация → не выдумывать победу по номеру открытой миссии;
— существующий прогресс новых миров не удалять даже если prerequisite ещё не выполнен: сохранять до открытия по общему правилу;
— неизвестную будущую/повреждённую схему не затирать пустым профилем.
Гость и пользователь host storage получают одинаковую логику по фактам своего доступного профиля. Межпортальную/межустройственную синхронизацию без соответствующего транспорта не обещать.

5. ЕДИНАЯ ПРОВЕРКА ВХОДА
Availability resolver используется selector, Continue, mission selection и любым route/campaign launch.
Одно только скрытие кнопки не должно оставлять обход через старый shortcut/deep link/share code.
Не блокировать всю существующую Time/Score/Daily/Rival/Relay игру. Ограничение относится к новым мирам по одной общей политике.
Новые миссии не включать в публичную Daily ротацию без совместимой политики доступа; действующий набор base-миссий продолжает работать.
Попытка запустить закрытый новый мир сообщает причину и ведёт в кампании, без silent launch/reset.
QA fixtures для проверки locked/unlocked состояний допустимы в dev/test. Не выпускать скрытую production-кнопку обхода вместо реализации правила.

Различать eligibility и наличие ресурсов:
locked_by_progress — не завершена первая кампания;
not_in_build — контент не включён в dev build;
load_failed — ресурсы есть в принятом составе, но не загрузились.
Сетевую ошибку не показывать как требование повторно пройти первую кампанию. После завершения загрузки открыть выбранный мир без потери прогресса.
В финальном RC оба новых мира обязаны быть включены/приняты: «скоро» или missing assets не закрывают задачу.

6. ВИЗУАЛ, МОБИЛЬНЫЙ ВВОД И 50 ЯЗЫКОВ
Сохранить стиль игры: художественные карточки/рамки/иконки и штатную типографику вместо стандартной голой HTML-формы.
Cover art брать из production art brief 08; тяжёлые игровые уровни/все музыкальные треки не предзагружать ради меню.
На телефоне — читаемый вертикальный список либо адаптивные карточки с явной навигацией. Не ужимать три desktop-колонки до нечитаемых плиток.
Учитывать safe area, длинные названия, RTL, touch targets и текущий MobileViewportLayout.
Keyboard/gamepad focus и кнопки Back/Cancel/Confirm работают без мыши; если gamepad поддержан в текущем RC, сохранить его flow.
Все новые заголовки/статусы/уведомления/подтверждения/reset/error/aria строки входят в обязательные 50 каталогов.
Locale switch не меняет selected campaign, доступность и сохранение.

Минимальные новые ключи (имена уточнить по текущему i18n registry):
campaigns.title; locked.requiresBaseCompletion; unlocked.title; unlocked.choose;
campaign.start; campaign.continue; campaign.replay; campaign.selectMission;
campaign.progress; campaign.reset.title/body/confirm; campaign.loadError/retry.
Для plural/параметров применять текущий контракт, не склеивать локализуемые предложения.

7. ПРИЁМКА
Fresh profile: первая кампания доступна, две новые видны и закрыты с причиной.
Незаконченная первая кампания не открывает новые миры.
Финал первой кампании открывает обе, показывает CTA и сохраняет факт.
Reload/возврат в главное меню/повтор первой кампании не теряют открытие.
Каждый новый мир запускается, сохраняется и продолжается отдельно; переключение не сбрасывает соседний.
Валидное старое завершённое сохранение мигрируется; повреждённое не перезаписывается; неподтверждённая победа не придумывается.
Time/Score/share route не обходят prerequisite; существующие режимы продолжают работать.
Нет production bypass/debug unlock, двойных rewards, ложного lock после network error.
Desktop/mobile/RTL/длинные строки/50 языков принимаются по существующему QA gate.
Приняты actual SHA/build_id, запись fresh→final→unlock→reload→launch обоих миров и заполненная menu_unlock_qa.csv.

# Alpha.14 — transport-ready storage for personal records

20 ноября 2026. Продолжение блока 08/13 поверх продуктового PR #16.

## Поведение

SaveService принимает тот же RecordStorage, который используют отдельные SDK-ветки. Счётчики больше не требуют прямого IndexedDB при выбранном платформенном транспорте. HostRecordStorage и BridgeRecordStorage выполняют read/merge/write профиля, полную резервную копию и при необходимости quarantine внутри единого обновления envelope. Прочие записи кампаний, PB и настроек сохраняются.

Очередь общая для экземпляров адаптера по ключу, а Web Locks координирует вкладки одного origin, включая асинхронный SDK read/write. Ошибка не отравляет очередь; повтор с тем же накопительным фрагментом не дублирует итог. Будущая версия внешнего envelope или статистики блокирует замену. При недоступном SDK нет перехода на другое хранилище. Интерфейс получает реальный scope от SaveService: устройство или профиль площадки.

## Проверки в этом PR

Добавлены десять контрактных сценариев (по пять для guest/Bridge): независимые экземпляры/конкурентная запись; отказ и повтор; backup/quarantine; будущие и повреждённые форматы; повторное чтение настроек и счётчиков. Ещё два браузерных сценария используют две реальные вкладки и медленный управляемый SDK mock. Они включены в матрицу Chromium/Firefox/WebKit.

Исходник должен пройти собственный CI. Предыдущие локальные 60/60 и полные маршруты относятся к предыдущему продуктовому source, а не являются доказательством этой новой реализации.

## Границы

Адаптеры подготовлены рядом с продуктовой реализацией. Подключение в initialize/lifecycle Яндекса и Playgama, сборки SDK, события pause/ad/reward и preview выполняются при переносе в существующие release-ветки. В этом PR основной web продолжает использовать IndexedDB. SDK-ветки и опубликованные сборки не изменены.

Web Locks обеспечивает согласование в пределах origin. При отсутствии API остаётся очередь экземпляров в одном JS-контексте; межвкладочная гарантия в таком браузере не заявляется. Конфликт облачных записей с разных устройств определяется SDK и не решается локальной блокировкой. Физические устройства, настоящее SDK-хранилище, upgrade/rollback старых опубликованных runtime и общий RC остаются открытыми.

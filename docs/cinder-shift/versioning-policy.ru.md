# Версии Cinder Shift

Продукт: `MAJOR.MINOR.PATCH[-alpha.N|-beta.N|-rc.N]`. MINOR добавляет контент или системы; PATCH исправляет текущую поставку; MAJOR обозначает новый этап продукта. Alpha — интеграция, beta — функции собраны, rc — кандидат после проверок. Публикация alpha не делает её стабильной. Историческая `0.7.0-rw2.c3` не переписывается. M-RW3 начинается с `0.8.0-alpha.1`; стабильная 0.8.0 зависит от M-RW4 и приёмки. Новый состав изменений получает новый release_id, номер не переиспользуется.

Ревизия — полный SHA исходного коммита. В интерфейсе sha7; полное значение доступно в настройках. Коммиты отчётов после проверенной runtime-ревизии учитываются отдельно и не подменяют SHA уже собранного артефакта.

Единственный владелец последовательного номера артефакта — workflow `Cinder Shift artifact`, файл `.github/workflows/cinder-build.yml`. Формат `cinder-v1.b<run_number>.a<run_attempt>`. Проверочные workflows создают только `verify.<run_id>.a<attempt>` и не выпускают кандидатов. Локальный формат `local.<UTC timestamp>[.dirty]`; кандидат требует чистого checkout. При переинициализации workflow меняется namespace `cinder-v1`, прежние IDs не повторяются.

Один объект из `scripts/build-metadata.mjs` встраивается в JS и записывается в build-manifest.json: version, release_id, milestone, source_sha, source_dirty, build_id, built_at_utc, channel, notes_id. UI никогда не запрашивает latest для подписи. Любое новое построение имеет новый build ID. Продвижение того же архива сохраняет его build ID и manifest; окружение назначения записывается в deployment-отчёт.

Полная техническая версия: `0.8.0-alpha.1+build.<run>.a<attempt>.g<sha7>`. Тег продукта: `v0.8.0-alpha.1`. SHA256 артефакта, deployment ID, runtime SHA, docs HEAD и site commit фиксируются при выпуске. Проверочные и локальные архивы не называются релизным кандидатом.

Release notes сравнивают release_id по SemVer, без части после `+`. Переход alpha.9 → alpha.10 корректен. Маркер подтверждения не понижается при rollback. Чистая установка хранит installed_release без ложного подтверждения просмотра; обновление существующего профиля подтверждается только после закрытия окна. Некорректный/future marker не перезаписывается. Сбой записи не блокирует игру и не обещает сохранение подтверждения между сессиями.

Save schema, content_version, rules hash и stable IDs независимы от версии продукта. Изменение подписи не сбрасывает сохранения, награды, PB и share codes. Перед поставкой новой схемы нужны отдельные миграции и проверки совместимости.

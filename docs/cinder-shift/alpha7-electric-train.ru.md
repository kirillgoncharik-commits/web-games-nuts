# Alpha.7 - последний электропоезд

18.11.2026. Следующая итерация M-RW3 по подробному room design. База remote `16579c684db37727e1e30869ea2fbcf11c2dc5be`, проверенный runtime alpha.6 `20b9080`. Общий статус INCOMPLETE / NOT RC.

## Реализация

- YU03-A: тяговая секция имеет реальную область урона и полный первый предвестник. B немедленно отключает секцию и открывает физический экран перехода. Возврат на A начинает новое предупреждение, а не скрытый старый таймер. Исходный contact ID сохранён.
- YU03-B: двери, опорные площадки и свет следуют текущему контуру A/B. Постоянная нижняя линия, устойчивые площадки и два рубильника сохраняют возврат. Скорость мира и jump envelope не меняются.
- YU03-C: постоянные трёхпозиционные сигналы показывают warning/active/safe независимо от контура, с отдельной формой индикатора. Сухие точки, исходный дрон и ремонт после участка сохранены.
- YU03-D: сначала B отключает тягу и подтверждает служебный переход. Только после этого начинается полный предвестник импульса передатчика. Следующие знакомые A/B действия настраивают изолятор и подтверждают передачу; тяга обратно не включается. Три исходных transmission IDs сохранены.
- Все A/B коллайдеры получили стабильные object IDs. Динамические объекты исключены из постоянного слоя материалов: отключённая дверь больше не остаётся нарисованной как сплошная стена. Переключение отклоняется при пересечении новой геометрии и при удалении опоры из-под стоящего героя.
- Просмотр первых CI кадров выявил перекрытие Миры табличкой контакта на мосту. Таблички контактов и рубильники перенесены в слой за героем; rig, anchors и положение Миры не менялись. Видимость подтверждена кадрами текущего CI и локального эквивалента.
- Пауза использует simulation clock, новый вход/Retry создаёт исходное состояние. Новых кнопок, ресурсов, наград или save schema нет. EN/RU HUD, причины урона и release notes alpha.7 обновлены. Полный production art/audio pack не заявлен.

## История проверок и исправлений

Source `24b9df3`: C02 full route PASS; 20 из 21 selected input cases PASS. Тоннельный helper остановился на различии signed zero: физическая вертикальная скорость равна -0, а Object.is отличает её от 0. Проверка заменена на Math.abs(vy)===0; ненулевые скорости по-прежнему запрещены. Та же причина воспроизведена в Firefox/WebKit.

C03 дошёл до YU03-B с HP6, обоими переключениями и первым контактом. Route driver пришёл на верхнюю необязательную полку при нужной x, но контакт находится на полу. Добавлен физический спуск вокруг края и обязательная проверка высоты контакта перед нажатием. Геометрия и механики игры не менялись; ни контакт, ни финальная проверка не обходятся. Исправленный driver проверен текущим успешным exact-source gate.

Первый локальный CLI запуск Chromium остановился с SIGABRT / EPERM: ни один из пяти случаев не дошёл до игрового ввода. Позже через native host выполнены шесть input случаев, полный C03 и отдельный audio rerun; все они PASS, servers закрыты.

Повтор `44172b3` выявил YU02-D: при нажатии на уже выбранный контакт у границы safe окна runtime мог перейти к соседнему рубильнику и сменить A обратно на B. Исправлен реальный приоритет взаимодействия: закрытый контакт в правильном контуре поглощает нажатие, не переключая питание. Добавлены модель и ordinary-input проверка. Driver ждёт не менее 600 мс остатка safe окна для доставки нажатия. Последующий source включает исправление перекрытия Миры; текущий полный selected gate PASS.

На `69e69db` новая проверка закрытого контакта и остальные 21 input cases PASS, но tunnel driver попытался прыгнуть из-под низкой постоянной опоры. Удар головой прервал прыжок, затем герой остался у укрытия до следующего импульса. Исправлен только маршрут обычного ввода: сначала выйти из-под навеса в безопасную фазу, затем прыгнуть на сухую опору. Геометрия, урон и требование HP6 сохранены.
